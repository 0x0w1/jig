# 프로젝트 유형별 버전 판정 기준

이 디렉토리는 SemVer의 `major.minor.patch` 의미를 프로젝트의 공개 인터페이스에 맞게 적용한 기준 문서 모음입니다. 원하는 유형의 문서를 골라 프로젝트의 `.spai/versioning.md`로 옮긴 뒤 실제 계약에 맞게 공개 인터페이스 목록을 다듬어 사용합니다.

## 공통 철학

- `patch`: 공개 인터페이스를 유지하는 호환 가능한 버그 수정
- `minor`: 기존 사용법을 유지하면서 공개 인터페이스에 기능을 추가하는 하위 호환 변경
- `major`: 기존 소비자가 수정 없이 계속 사용할 수 없는 비호환 변경

AI가 작업했는지, 얼마나 많은 코드를 생성했는지, 파일을 몇 개 바꿨는지, 구현에 시간이 얼마나 걸렸는지는 버전 등급과 무관합니다. 판정 대상은 오직 릴리즈 전후의 공개 계약과 소비자 호환성입니다.

공통 판정 원칙과 애매한 사례는 [공통 SemVer 원칙](common.md)을 먼저 확인합니다.

## 유형 선택

| 프로젝트 유형 | 공개 인터페이스의 중심 | 기준 문서 |
|---|---|---|
| API 서버 | endpoint, 요청·응답, 인증, 이벤트 | [API 서버](api-server.md) |
| 웹 클라이언트 | 사용자 흐름, URL, 브라우저 저장 상태 | [웹 클라이언트](web-client.md) |
| 모바일 앱 | 사용자 흐름, deep link, 로컬 데이터, 서버 호환성 | [모바일 앱](mobile-app.md) |
| 데스크톱 앱 | 파일 형식, 설정, OS 통합, 업데이트 | [데스크톱 앱](desktop-app.md) |
| 라이브러리·SDK | export, 타입, 호출 규약, 런타임 지원 | [라이브러리·SDK](library-sdk.md) |
| CLI 도구 | command, option, exit code, 기계 판독 출력 | [CLI 도구](cli-tool.md) |
| 백그라운드 워커 | 메시지 schema, retry, 순서, side effect | [백그라운드 워커](background-worker.md) |
| 인프라 프로젝트 | module 입출력, 리소스 계약, 운영 영향 | [인프라](infrastructure.md) |
| 모노레포 | 패키지 경계와 버전 전파 전략 | [모노레포](monorepo.md) |

여러 성격이 섞여 있으면 소비자별 공개 인터페이스를 모두 적고, 같은 변경에 여러 판정이 나오면 가장 높은 등급을 사용합니다. 예를 들어 API 서버와 웹 클라이언트를 함께 배포하더라도 외부 API 소비자가 있다면 UI 호환성만으로 등급을 낮출 수 없습니다.

## 적용 방법

1. 프로젝트를 실제로 사용하는 소비자를 식별합니다.
2. 가장 가까운 유형 문서를 `.spai/versioning.md`의 초안으로 사용합니다.
3. `## 공개 인터페이스`를 프로젝트의 실제 계약으로 수정합니다.
4. 자동화·테스트·배포 절차가 아닌 소비자 호환성을 기준으로 예시를 검토합니다.
5. 파일을 저장소에 커밋해 사람과 릴리즈 에이전트가 같은 기준을 읽게 합니다.

이 문서들은 버전 등급을 판정합니다. 빌드, 스토어 심사, 단계적 배포, 롤백 같은 릴리즈 실행 절차는 별도 playbook에서 관리해야 합니다.
